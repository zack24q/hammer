## 运行方式

推荐使用 Node.js 22.15+（或更新的 LTS 版本），需要支持 `--test-timeout`。先安装项目依赖，并确保子模块已检出：

```sh
git submodule update --init --recursive
npm ci
npm test
npm run typecheck:overlay
```

只运行开播、推流及相关回归：

```sh
npm run test:streaming
```

只运行某个模块：

```sh
node -r ts-node/register/transpile-only --test --test-timeout=10000 tests/song-request.test.cjs
```

测试文件由运行器在独立进程执行。HTTP、账号、Cookie、OBS 使用模拟对象；注入的脚本在 VM 中运行；事件桥使用本机 `127.0.0.1` 的随机端口和真实 WebSocket 客户端。测试不会登录真实账号、开启直播、访问音乐服务或修改实际 OBS 设置。异步乱序使用可控 Promise，缓存过期使用模拟时间，事件转发用消息顺序判断，避免依赖任意等待时间。

## 测试促成的修复

- 非法歌单索引不再误删歌曲；恢复存储时修正无效播放索引。
- 无当前歌曲时，切歌权限判断和 OBS 模板渲染不再崩溃。
- OBS 模板一次替换原始占位符，元数据中的 `$`、占位符文字保持原样，未知字段保留。
- 快速切歌或页面卸载后，迟到的歌曲信息不再覆盖播放器，也不再错误结束最新请求的加载状态。
- 空指令前缀不匹配任意弹幕；重叠前缀优先选择较长的完整指令。
- 事件桥在真正开始监听后才报告成功；端口占用可捕获并重试；无响应客户端不会无限阻塞关闭。

歌单导入同时改为保存实际导入的 ID；OBS 同步失败会被界面捕获并提示。

## 覆盖边界与桌面验收

这些测试验证业务逻辑和服务协议，不代表完整的端到端覆盖。以下场景仍需要在桌面应用中验收：

1. 真实 B站登录、页面改版、开播资格与人脸验证流程，成功后手动复制和填写实际 OBS。
2. 网络断开时两个内嵌页面的错误提示、重新加载和 75% 缩放。
3. 真实音频播放、连续切歌、播放结束自动切歌、在 OBS 中显示文字。
4. macOS 关闭窗口后从 Dock 恢复，以及开发启动进程结束后的 Electron 退出。
5. 悬浮框真实跨系统置顶、鼠标穿透、滚动与设置面板交互。

macOS 已通过实际 Electron 桌面冒烟检查，使用锤子的主进程、实际 preload/renderer 与本地事件桥验证文本/表情/SC/礼物/舰长、100 条上限与统计排除、置顶/穿透/设置弹窗暂停及恢复、关于版本、内容保护开关 IPC 和关闭重开。可以在 `npm run package` 后运行 `npm run test:overlay:desktop` 重现；该检查使用临时用户目录及模拟 HTTPS 页面，不登录或开播。需确保本地事件桥默认端口 9696 空闲。Windows/Linux 的系统级行为尚未实机验证，Linux 状态机由单元测试覆盖。

最新版悬浮框代码位于保持干净的 `chat-overlay` Git 子模块中；原生窗口控制位于 `src/main/chatOverlay.ts`。测试直接加载上游设置/运行时状态和根项目原生控制器。保存或交付改动时只需更新根项目的子模块指针。

`npm test` 使用 transpile-only 执行，不代替 TypeScript 类型检查。新版悬浮框使用 `npm run typecheck:overlay` 单独检查，采用上游的 bundler 模块解析。根项目旧的 `node` 模块解析仍会使全量 `tsc --noEmit` 出现既有诊断；新接入部分由 bundler 模块解析下的专门检查覆盖。编译器已更新到 TypeScript 6，以满足最新版事件类型包的 peer 依赖，避免干净安装失败。发布前应分别检查 ESLint、类型诊断和 `npm run package` 的结果。
