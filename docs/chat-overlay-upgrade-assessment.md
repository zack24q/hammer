# chat-overlay 升级评估

> 历史调研记录。用户已决定直接接入最新版，当前实现已切换到 chat-overlay 1.1.1 / master f940914，不迁移旧配置。实现状态见 [新版接入说明](chat-overlay-integration.md)。


评估日期：2026-10-09。结论：新版有值得采用的功能，但当前不适合直接更新子模块指针；先确定许可证方案，再进行有针对性的集成升级。

## 对比基线

- 当前锁定：[`6d061d0`](https://github.com/laplace-live/chat-overlay/commit/6d061d0587132d6edcbb32eea84bffbb7c77bfd0)，2025-06-15，`package.json` 标记为 1.0.0，早于正式 v1.0.0 标签。
- 远端 master：[`f940914`](https://github.com/laplace-live/chat-overlay/commit/f94091413d50b0d53f666b6aa9d94b83b886b0c2)，2026-09-08，通过 GitHub API 核对，与本地远端引用一致。
- 最新稳定版：[`v1.1.1`](https://github.com/laplace-live/chat-overlay/releases/tag/v1.1.1)，2026-08-31，指向 `2567ad8`。
- 当前节点到 master 有 151 个提交；到 v1.1.1 有 149 个。master 相比 v1.1.1 仅修改构建工作流，没有额外产品功能，因此升级目标应锁定稳定标签。
- 本地另有未提交修改：`src/renderer.tsx` 调用抽取的 `src/utils/eventState.ts`，以及根项目悬浮框测试。评估过程中没有切换节点或改写这些文件。

## 升级需要解决的问题

### 1. 许可证已经变更

当前锁定节点的 LICENSE 是 MIT；上游在 [`c283ab2`](https://github.com/laplace-live/chat-overlay/commit/c283ab2) 将 LICENSE 改为 AGPL-3.0，新版 `package.json` 同样标记 AGPL-3.0。

锤子目前标记 MIT，而且直接把子模块的渲染代码和 preload 打包进自己的应用。升级需确认组合分发的许可说明及对应源码提供方式，不能仅以当前 MIT 说明作为新版全部代码的许可。直接复制新版实现或挑选提交也需要遵循相关许可证。

若计划维持现有许可方案，建议在现有实现上独立开发需要的功能，或向上游确认其他授权方式；若接受 AGPL 的分发条件，可继续做新版适配。

### 2. 仅更新子模块不能获得完整功能

根项目仅使用子模块的 `index.html`、渲染器和 `src/preload.ts`；运行的是 `src/main/main.ts`，没有运行上游 `src/main.ts`。

新版 preload 新增 `get-app-version`、`open-external`、`set-click-through-suspended`、`set-title-bar-height`、`title-bar-hovered`。根项目没有这些同名处理器。About 组件在挂载时就查询版本，缺失处理器会造成 Promise 拒绝；Linux 感应窗口以及暂停/恢复穿透也需要移植到锤子的主进程。

### 3. 构建配置和依赖不匹配

上游使用 Tailwind 插件、`@` 指向子模块 `src` 的路径别名；当前 `vite.renderer-chat-overlay.config.ts` 两者都没有。新版还引用 `tw-animate-css`。

当前依赖中缺少 `@tabler/icons-react`、`class-variance-authority`、`tailwind-merge` 和 `tw-animate-css`。`dayjs` 虽然当前可从依赖树找到，但新版渲染器直接使用它，集成时应显式声明。子模块自身 `package.json` 的依赖升级不会自动写入根项目的依赖和锁文件。

上游独立应用使用 Electron 42、TypeScript 6；锤子使用 Electron 36、TypeScript 5.8。集成渲染器不意味着必须照搬整套工具链，宜先保留根项目工具链并验证实际兼容性。

### 4. 上游显示开关存在回归

[`src/components/events.tsx`](https://github.com/laplace-live/chat-overlay/blob/2567ad86634ac180d7318366a481a21600854b5c/src/components/events.tsx#L229) 的旧 `renderMessage` 函数有互动、免费礼物、入场特效的过滤，但实际列表改为直接渲染 `EventLite`，没有调用该函数，也没有执行这三项过滤。

已用上游真实 `ChatEvents` 组件进行模拟渲染：提供互动、银瓜子礼物、入场特效三种事件，三个开关全部关闭与全部开启时，三种事件均渲染，HTML 完全相同。测试仅替换图标、状态来源和叶子内容组件，验证的是消息列表是否执行过滤。因此不能把这三个开关视为已经可用的新功能，升级时应先修复并补回归测试。

### 5. 历史消息和设置会改变

- 消息上限由当前的 500 条变为 100 条，且统计类事件除 `online-update` 外会先占用存储再被列表隐藏。
- 当前设置使用 `overlay-opacity`、`overlay-serverHost` 等分散键；新版使用 Zustand 的 `overlay-settings`，未提供旧键迁移。直接升级会恢复默认配置，包括连接地址、令牌和穿透/置顶设置。
- 新版默认 `alwaysOnTop: false`，并会在挂载时应用，导致锤子创建窗口时的 `alwaysOnTop: true` 被覆盖。
- 当前本地抽取的消息裁剪、滚动、鼠标穿透逻辑及 5 个测试需要接到新版结构，不能简单丢弃。

## 建议路线

1. 目前继续使用锁定节点，优先确认是否接受新版许可条件。
2. 若接受，升级目标选 v1.1.1；先适配依赖、Tailwind/路径别名、IPC 和设置迁移，不引入独立应用的自动更新或整套发布配置。
3. 修复显示开关，保留 500 条消息和当前默认置顶行为；将本地回归测试迁移到新版状态模块，增加表情、事件过滤、旧设置迁移和启动 IPC 测试。
4. 验证 Windows/macOS 的穿透、拖动、设置弹窗、关闭、重新打开及打包；需要 Linux 时再引入标题栏感应窗口和 XWayland 处理。

此次完成了提交/源码/依赖对比和上游消息列表的模拟验证，未实际升级或运行新版完整应用，也未提交或推送任何改动。
