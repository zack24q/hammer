# chat-overlay 升级成本

> 历史调研记录。用户已决定直接接入最新版，当前实现已切换到 chat-overlay 1.1.1 / master f940914，不迁移旧配置。实现状态见 [新版接入说明](chat-overlay-integration.md)。


评估日期：2026-10-09。目标：从 `6d061d0` 升级到稳定标签 `v1.1.1`（`2567ad8`），服务于主播自用弹幕悬浮窗。

结论：在接受新版许可条件、保留现有采集链路和工具链的前提下，可运行原型估算 4–8 小时；完成 Windows/macOS 适配、回归及分发准备，预算 24–40 个有效开发小时，即约 3–5 人日。Linux 完整支持另加 16–32 小时。以下是熟悉项目的开发者工作量估算，不是已经完成的升级工时，也不含等待设备、许可决定或外部授权的时间。

## 预算范围

基础预算包含：

- 新版消息/表情/礼物/SC/红包/抽奖展示、字号、自定义 CSS 和设置界面。
- 保留默认置顶、500 条历史、窗口位置、内容保护、当前 Event Bridge 连接方式。
- 迁移已有设置，处理本地子模块修改，修复已发现的上游回归。
- Windows/macOS 的窗口行为、功能及打包验收。
- 新版许可证说明及对应源码分发准备。

基础预算保留锤子的主进程和现有 Electron/Vite/TypeScript，不包含换采集器、自建服务器、上游独立应用自动更新、签名公证体系、全面中文化，也不包含 Linux 感应窗口。

## 实际试验降低了哪些不确定性

没有切换工作区的子模块节点。用 `git archive v1.1.1` 导出到临时目录，只在那里安装缺失依赖并构建，根项目依赖和锁文件未修改。

| 试验                                                          | 结果                                                                               | 对成本的影响                                                  |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 直接使用当前悬浮窗构建配置                                    | 缺少 `@tabler/icons-react` 等依赖，构建失败；CSS 还需要 `tw-animate-css`           | 不能只更新指针                                                |
| 补齐依赖、Tailwind 插件及 `@` 别名                            | 新版渲染器生产构建通过                                                             | 构建适配工作可控                                              |
| 使用根项目 TypeScript 5.8.3，对新版 renderer/preload 单独检查 | 使用 bundler 模块解析后 0 条类型诊断                                               | 不必为此次升级引入 TypeScript 6；建议单独的悬浮窗类型检查配置 |
| 使用当前 Electron 36.9.5 启动新版渲染器                       | 界面启动、连接本机模拟 WebSocket、文本和表情显示、设置弹窗打开，无记录到的 JS 错误 | 不必先升级 Electron 42                                        |
| 新版的默认置顶                                                | 启动发送 `set-always-on-top: false`                                                | 需要保留旧默认值或迁移用户值                                  |
| 新版显示过滤                                                  | 三个显示开关关闭，互动、免费礼物和入场特效仍显示                                   | 需要修复并测试                                                |

临时环境复用了根项目实际安装的 Vite 5.4.21、React 19.3.0、Radix 1.7.0、Tailwind 插件 4.3.3、Event Bridge SDK 1.2.2。

Electron 试验使用上游实际 preload，补了模拟 IPC 处理器，并使用独立临时用户目录。它验证渲染器兼容性，未验证真实系统鼠标穿透、置顶、OBS 内容保护或 Windows；没有连接 B站或操作 OBS。根项目原有全量 TypeScript 诊断也没有因此自动消除。

| 设置与本地改动迁移 | 从 `overlay-*` 旧键迁移到 `overlay-settings`；服务器密码映射为新令牌字段；优先已有新版设置，验证数值；保留默认置顶、500 条历史和现有辅助逻辑；保留升级回退所需旧数据 | 3–5 小时       |

| 自动化回归         | 迁移原 5 个悬浮窗用例；新增设置迁移、事件过滤、表情、IPC 和重连/关闭用例；运行现有全量回归                                                                           | 4–6 小时       |
| 桌面和打包验收     | Windows/macOS 的拖动、置顶、穿透与弹窗恢复、窗口关闭/再开、位置恢复、OBS 内容保护、多屏/DPI；核对开发与生产包                                                        | 6–10 小时      |
| 许可与源码交付     | 确认分发方案后更新许可声明、版权/修改说明、附完整许可证；为安装包提供包括子模块及补丁的对应源码与构建说明                                                            | 2–4 小时       |
| **合计**           | **Windows/macOS 可发布范围**                                                                                                                                         | **24–40 小时** |

主要根项目改动预计涉及 `package.json`、`package-lock.json`、悬浮窗 Vite 配置、`src/main/main.ts`、悬浮窗类型检查配置、测试和分发说明；子模块主要涉及 settings/runtime store、消息列表及本地辅助函数。若将配置改成 `.mts`，需同步 Forge 中引用的文件名。

| 更换 LAPLACE 采集链路                     | 不纳入本次预算，需另评估 | 属于弹幕数据来源的可靠性工程，升级显示模块不会解决                                                                  |

## 体积、运行与维护成本

隔离生产构建的 JS+CSS 总量：

|           | 当前构建     | 新版隔离构建 | 增量                     |
| --------- | ------------ | ------------ | ------------------------ |
| 原始文件  | 246,010 字节 | 608,505 字节 | 362,495 字节，约 354 KiB |
| gzip 对比 | 75,966 字节  | 156,930 字节 | 80,964 字节，约 79 KiB   |

这是前端产物对比，不是最终安装包测量，gzip 也不是本项目安装包的压缩算法。当前 Forge Vite 插件默认只打包 `.vite` 产物，图标库的完整开发依赖不会因此自动全部进入应用；升级显示模块也不需要另一份 Electron 运行时。

没有测量 CPU、内存、图片缓存或延迟，不能据此承诺性能不变。新版渲染更丰富，保留 500 条历史后的实际资源占用应在验收时检查。

保持现有事件源和本地桥，不需要为了此次升级新增服务器或付费服务。主要成本是开发、验收，以及后续维护少量集成补丁：上游仍是独立应用，没有提供稳定的嵌入组件接口。应固定稳定标签，记录补丁，在后续升级时复查 IPC、状态存储及消息列表；不能依赖自动跟随 master。

许可证方案的决定时间、其他授权沟通和实际法律审查不包含在 2–4 小时的交付整理预算内。决定前不自动修改锤子的许可。

## 建议

若确定采用新版全部显示能力，按 Windows/macOS、保留现有工具链、暂不做 Linux 的范围安排 3–5 人日较合理。技术上具备升级可行性，主要不确定性剩在跨平台窗口行为和实际直播验收。

若目标仅是“主播能更舒服地看弹幕”，可继续在旧实现上做字号和表情等针对性增强，不必同时承担整套 UI、状态存储和许可切换。此路径需要单独列清需求后估算，不能把它当成本次已验证的新版升级。

本次只做临时试验和成本文档，没有升级工作区、修改应用行为、提交或推送。
